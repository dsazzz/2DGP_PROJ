# 개발 기록

- 날짜 / 2026-11-21
- 단계 / 1. 고정 물리 루프 분리
- 변경 파일 / `game/core/loop.py`의 `FixedStep`, `game/main.py`의 `main`, `game/world/scene.py`의 `handle_events`·`update`, `tools/playground.py`의 `LocalLoop.run`, `tools/benchmark_electric.py`의 `main`, 관련 테스트와 문서
- 바꾼 이유 / 게임과 수동 테스트 공간에서 같은 틱 계산을 사용한다. 키다운은 다음 물리 틱에서 한 번씩 처리하고, 재불러오기에 걸린 시간은 물리 누적에서 제외한다. `--perf`에 갱신 시간을 표시한다.
- 이전 → 이후 수치 / 게임 물리 `1/60` 직접 지정 → `FIXED_DT = 1/60` 공통 사용. 전류 벤치의 1초 샘플 144개 → 60개. 화면 출력 목표 144FPS. 한 번에 누적하는 시간은 최대 0.1초다.
- 새 이름 / `PHYSICS_HZ`·`FIXED_DT`는 물리 주파수와 기존 고정 갱신 간격, `FixedStep`은 누적 시간과 기준 시각 계산, `alpha`는 한 틱에 대한 남은 시간 비율, `_queued_actions`는 점프·대시 조작과 기존 착지 버퍼에 넘길 키다운 기록에 대응한다.
- 확인 방법 / `python tools/check.py` 62개 통과. 모의 시계에서 60회 출력과 72회 고정 갱신을 실행해 `--perf`가 물리 스텝당 2.00ms를 표시하는지 확인했다. 오프스크린 전류 벤치에서 현재 맵 갱신·출력은 0.224ms/프레임이었다. 직접 플레이는 `python -m game --perf`에서 Space/Z, Shift/X, F5와 `update … ms/step`을 확인한다.
- 시간 값 점검 / 게임 코드의 144는 출력 목표, 테스트의 144Hz는 30·60·120·144Hz 비교 검증, 수동 공간의 나머지 144는 좌표·크기·색이다. 기본 주기를 따라야 하는 검사와 전류 벤치는 공통 60Hz 값을 사용한다. 전류·이펙트 프레임 번호는 초 단위 재생 시간에서 계산한다.
- 남은 문제 / 60Hz 위치를 144FPS로 그대로 표시한다.

- 단계 / 2. 수평 가감속
- 변경 파일 / `player.py`의 `_update_run_velocity`·`_update_motion`·벽 충돌과 속도 단계 적용, `scene.py`의 `_step`, `player_view.py`의 착지 예상, `player-settings.json`, 이동 검사와 문서.
- 바꾼 이유 / 누름·놓음·방향 전환에 가감속을 적용하고 벽에서 수평 속도를 0으로 맞춘다. 일반 이동은 양쪽 키가 눌리면 감속한다.
- 이전 → 이후 수치 / 즉시 180–360 → 가감속을 거쳐 270–540단위/초. 1단계 `run_accel` 3000, `run_reduce` 1200단위/초², `air_mult` 0.65. 시작점에서 6틱(0.10초) 동안 17px 이동해 270에 도달하고 키 해제 뒤 10px 이동했다.
- 새 이름 / `vx`는 기존 입력 방향과 최고속도의 곱으로 즉시 구하던 수평 속도를 보관한다. `move_speeds`는 단계별 최고속도, `run_accel`·`run_reduce`는 가감속과 최고속도 초과 감속, `air_mult`는 공중 가감속 비율에 대응한다.
- 확인 방법 / `python tools/check.py` 63개와 `python tools/render_preview.py` 통과. 60Hz에서 가속·정지·반전·공중 가속·벽 충돌을 확인했다. 현재 맵 점프 발판의 128px 도약은 전류를 피하는 경로에서 확인했다.
- 남은 문제 / 발판 중앙에서 제자리로 도약하면 변경 전후 모두 70.70px에서 전류에 접촉한다. 현재 맵에는 출구가 없어 클리어 판정은 확인할 수 없다. 복구 태그는 `movement-before-horizontal`이다.

- 단계 / 3. 중력·낙하·정점 보정
- 변경 파일 / `player.py`의 `vertical_motion`·`set_vertical_input`, `scene.py`의 `_step`·`_clear_input`, `player_view.py`의 정점·착지 예정 표시, `player-settings.json`, 수동 테스트 공간, 회귀 검사와 문서.
- 바꾼 이유 / 점프 키를 누른 동안 정점 부근 중력을 줄이고, 아래 키의 눌림 여부에 따라 낙하 상한을 적용한다. 모델과 착지 예측이 같은 세로 이동 계산을 쓴다.
- 이전 → 이후 수치 / `gravity` 900 → 2700, `apex_speed` 110 → 120. 1단계 낙하 상한 일반 480·아래 키 720단위/초. 정점 보정 중에는 중력 50%.
- 새 이름 / `max_fall`·`fast_max_fall`은 일반·빠른 낙하의 속도 상한, `jump_held`·`down_held`는 틱에서 확인한 키 상태, `near_apex`는 기존 정점 애니메이션 속도 비교, `vertical_motion`은 기존 세로 변위·속도 계산에 대응한다.
- 확인 방법 / 자동 검사 65개 및 오프스크린 미리보기 통과. 60Hz에서 1단계 일반 점프 21.33px(즉시 해제)·23.85px(유지), 낙하 상한 480·720을 확인했다. 10단계의 현재 맵 발판 오른쪽 진입은 127.92px였다. [디버그 기록](debug.md#중력과-낙하)
- 남은 문제 / 일반 점프 최고점은 목표 64px보다 낮다. 현재 맵에서 시험한 1단계 발판 진입은 전류에 접촉했고, 출구가 없어 클리어 판정을 확인할 수 없다. 복구 태그는 `movement-before-gravity`다.
